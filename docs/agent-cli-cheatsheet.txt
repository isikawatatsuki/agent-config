AI AGENT CHEAT SHEET                                  Ctrl+/ で表示 / q で閉じる
===============================================================================

[ まず覚える ]
  /            コマンド候補を表示（Claude Code / OpenCode / Codex）
  @            ファイルを指定
  Esc          実行を止める / ダイアログを閉じる
  Ctrl+C       実行を止める / 入力を消す
  Ctrl+J       改行（Claude Code / OpenCode）

[ herdr 0.9 ]  prefix は Ctrl+B
  Ctrl+/             この一覧
  Ctrl+B ?           herdr 標準ヘルプ
  Ctrl+B Shift+N     ワークスペースを作成
  Ctrl+B W           ワークスペースを選択
  Ctrl+B C           タブを作成
  Ctrl+B N / P       次 / 前のタブ
  Ctrl+B V / -       左右 / 上下に分割
  Ctrl+B H/J/K/L     ペインを移動
  Ctrl+B Z           ペインを最大化
  Ctrl+B X           ペインを閉じる
  Ctrl+B Q           デタッチ
  注: 正確な現在値は Ctrl+B ? で確認する。

[ Claude Code ]
  ? (入力が空)       ショートカット一覧
  /help              ヘルプ
  Shift+Tab          権限モードを切り替える
  Ctrl+O             詳細トランスクリプト
  Ctrl+G             長い入力を外部エディタで編集
  Ctrl+R             入力履歴を検索
  Ctrl+T             タスクリストを表示/非表示
  Esc Esc            巻き戻しメニュー（入力が空のとき）
  claude -c          直近セッションを続ける
  claude -r          セッションを選んで再開

[ OpenCode ]  leader は Ctrl+X
  Ctrl+Alt+K         全キーバインド一覧（which-key）
  Ctrl+P             コマンド一覧
  Ctrl+X M           モデル選択
  Ctrl+X A           エージェント選択
  Ctrl+X L           セッション一覧
  Ctrl+X N           新規セッション
  Tab / Shift+Tab    エージェントを切り替える
  F2 / Shift+F2      最近のモデルを切り替える
  Esc                実行を止める

[ Codex ]
  ?                  ショートカット一覧
  /help              コマンド一覧
  /status            現在の設定とコンテキスト
  /model             モデルと推論強度を変更
  /permissions       権限を変更
  /plan              計画モード
  /review            変更をレビュー
  /diff              Git 差分を表示
  /compact           会話を圧縮
  codex resume       セッションを選んで再開

[ 用途別プロンプト ] そのまま入力して、[] だけ置き換える

  壁打ち
    「[テーマ]を壁打ちしたい。まだ実装しないで。前提を整理し、重要な質問を
    1つずつ聞き、選択肢・利点・欠点を示して。」

  調査
    「[テーマ]を調査して。結論、根拠、代替案、リスク、未確認事項の順で整理し、
    外部情報には出典URLと確認日を付けて。まだ実装しないで。」

  計画
    「[目的]の実装計画を作って。既存コードを確認し、変更ファイル、手順、
    成功条件、検証方法、リスクを示して。まだ実装しないで。」

  実装
    「[目的]を実装して。既存の設計に合わせて最小変更にし、関連テストを実行。
    失敗したら原因を直して再検証し、最後に変更点と結果を報告して。」

  バグ調査・修正
    「[症状/エラー]を再現し、根本原因を特定して最小修正して。回帰テストを追加し、
    関連テスト・lint・型チェックを実行して。」

  コードレビュー
    「[対象]をレビューして。バグ、回帰、セキュリティ、保守性、テスト不足を
    重要度順に、file:line と修正案付きで報告して。コードは変更しないで。」

  説明
    「[対象]を、背景 -> 全体像 -> 処理の流れ -> 具体例 -> 注意点の順で、
    初見の開発者向けに説明して。コード参照は file:line を付けて。」

  文書化
    「[対象]をMarkdownで文書化して。対象読者、目的、前提、手順、例、
    トラブルシューティングを含め、既存文書の表現に合わせて。」

[ 依頼を明確にする5点 ]
  目的: 何を達成したいか
  対象: どのファイル・画面・機能か
  制約: 変えてはいけないもの、期限、互換性
  完了条件: 何ができれば終わりか
  検証: どのテスト・操作で確かめるか
